# 评估指标定义

本文档定义降水预报评估中使用的各类指标。

---

## 分类评估指标

降水预报本质上是二分类问题：预报是否 ≥ 阈值，观测是否 ≥ 阈值。

### 混淆矩阵

|                | 观测：是 | 观测：否 |
|----------------|---------|---------|
| **预报：是**   | Hits (a) | False Alarms (b) |
| **预报：否**   | Misses (c) | Correct Negatives (d) |

---

## 核心指标

### TS (Threat Score / CSI)

**定义**:
```
TS = Hits / (Hits + Misses + False Alarms)
   = a / (a + b + c)
```

**含义**: 
- 综合考虑命中、漏报、空报的技巧评分
- 去除了"正确否定"（没下雨也没报）的影响

**范围**: [0, 1]，1 最好

**优点**:
- 不受大量 TN 的影响，适合稀有事件（如降水）
- 综合评价

**缺点**:
- 不能区分漏报和空报谁更严重
- 对 BIAS 不敏感

**业务含义（经验值，仅供快速沟通）**:
- TS ≥ 0.3: 相对可用
- 0.2 ≤ TS < 0.3: 勉强可用
- TS < 0.2: 该量级不可用

> 这些是**沟通用的经验分级，不是业务发布标准**：同样的 0.3，小雨和特大暴雨的含义
> 完全不同。业务可用性要**按量级分别确认**，并先过 `diagnostic-rules.md` 的样本量门槛。

---

### POD (Probability of Detection / Hit Rate)

**定义**:
```
POD = Hits / (Hits + Misses)
    = a / (a + c)
```

**含义**: 实际发生的降水中，被预报命中的比例

**范围**: [0, 1]，1 最好

**别名**: 
- Hit Rate
- Recall
- Sensitivity

**优点**:
- 直观衡量漏报情况
- 适合评估预警能力

**缺点**:
- 不考虑空报
- 可以通过"全报"达到 POD=1

**业务含义**:
- POD > 0.7: 漏报较少
- POD < 0.5: 漏报严重

---

### FAR (False Alarm Ratio)

**定义**:
```
FAR = False Alarms / (Hits + False Alarms)
    = b / (a + b)
```

**含义**: 所有预报中，空报的比例

**范围**: [0, 1]，0 最好

**优点**:
- 直观衡量空报情况
- 业务关注度高（误报影响可信度）

**缺点**:
- 不考虑漏报
- 对预报频率敏感

**业务含义**:
- FAR < 0.3: 空报控制良好
- FAR > 0.6: 空报严重

---

### BIAS (Frequency Bias)

**定义**:
```
BIAS = (Hits + False Alarms) / (Hits + Misses)
     = (a + b) / (a + c)
```

**含义**: 预报频率 / 观测频率

**范围**: [0, +∞]
- BIAS = 1: 频率完美
- BIAS > 1: 预报频率偏高（高报）
- BIAS < 1: 预报频率偏低（低报）

**优点**:
- 诊断系统性偏差
- 指导阈值调整

**缺点**:
- 不反映空间匹配质量
- BIAS=1 不代表预报准确

**业务含义**:
- 0.9 ≤ BIAS ≤ 1.1: 频率良好
- BIAS > 1.5 或 < 0.7: 系统性偏差明显

---

## 指标关系

### TS vs POD vs FAR

```
TS = 1 / (1/POD + 1/(1-FAR) - 1)
```

**含义**: TS 是 POD 和 FAR 的调和平均

**推论**:
- 要提升 TS，需同时提高 POD、降低 FAR
- 只提高 POD（全报）会导致 FAR 升高，TS 不一定提升

---

### BIAS vs POD vs FAR

```
POD = BIAS * (1 - FAR)
```

**推论**:
- BIAS > 1 + 高 FAR: 预报频率过高是主因
- BIAS ≈ 1 + 高 FAR: 时空匹配是主因
- BIAS < 1 + 低 POD: 预报频率不足是主因

---

## 指标组合诊断

### Case 1: 高 TS + 高 BIAS + 高 FAR

**现象**: 整体技巧不错，但空报多

**诊断**: 预报频率偏高，但时空匹配尚可

**建议**: 提高阈值或应用 BIAS 校准

---

### Case 2: 低 TS + 低 BIAS + 低 POD

**现象**: 技巧低，漏报多

**诊断**: 预报频率不足

**建议**: 降低触发阈值

---

### Case 3: 低 TS + BIAS≈1 + 高 FAR + 低 POD

**现象**: 频率对了，但技巧低

**诊断**: 时空匹配问题

**建议**: 
- 检查插值方法
- 引入邻域验证
- 评估观测质量

---

### Case 4: 低 TS + BIAS≈1 + 低 FAR + 低 POD

**现象**: 频率对，空报少，但技巧低

**诊断**: 预报过于保守，只报高信度区域

**建议**: 适当放宽阈值，平衡 POD 和 FAR

---

## 阈值依赖性

所有分类指标都依赖于**降水阈值**。

### 常用阈值

| 阈值 (mm) | 降水等级 | 业务关注 |
|----------|---------|---------|
| 0.1      | 有雨/无雨 | 通用评估 |
| 10.0     | 中雨    | 日常预警 |
| 25.0     | 大雨    | 强降水能力 |
| 50.0     | 暴雨    | 极端事件 |

### 不同阈值的意义

- **0.1mm**: 评估整体技巧，样本量大
- **10mm**: 评估实际业务关注的降水
- **25mm/50mm**: 评估强降水和极端事件能力

---

## 时效依赖性

指标随预报时效变化。

### 典型模式

```
TS: 短期高 → 中期平稳 → 长期衰减
POD: 短期高 → 长期缓慢下降
FAR: 短期低 → 长期缓慢上升
BIAS: 相对稳定（如有系统偏差）
```

### 关键时效段

- **24-72h**: 短期预报，技巧最高
- **72-168h**: 中期预报，业务关注重点
- **168-360h**: 中长期预报，技巧明显下降
- **360h+**: 次季节尺度，技巧接近气候态

---

## 累积窗口

降水通常按累积窗口评估。

### 常用窗口

- **24h 累积**: 日降水，最常用
- **6h 累积**: 次日尺度，强对流
- **3h 累积**: 短时强降水

### 窗口选择原则

- 业务需求：预警通常用 24h
- 物理过程：对流用 3-6h，层云用 24h
- 样本量：窗口越短，样本越少

---

## 空间聚合

评估时可能在不同空间尺度聚合。

### 点对点验证

- 格点对格点比较
- 对位置误差敏感
- 常导致"双重惩罚"问题

### 区域平均

- 对某区域平均后比较
- 平滑位置误差
- 损失空间细节

### 邻域方法 (FSS)

- 考虑邻域内匹配
- 缓解双重惩罚
- 更适合高分辨率模式

---

## 统计显著性

### 样本量要求

```
降水 ≥ 0.1mm: 样本量通常充足
降水 ≥ 25mm: 样本稀疏，需谨慎解读
```

### 样本量门槛（比置信区间更常用的硬约束）

| 条件 | 处理 |
|---|---|
| 事件数 = 0 | 不可评定，不下任何技巧结论 |
| 0 < 事件数 < 50 | 仅参照，曲线上标"样本少" |

置信区间需要**逐样本（或逐站逐时次）的重采样**，只有汇总列联表时算不出可信区间；
若确需区间估计，应当回到原始配对样本（`diagnostics/scores_detail.csv` 或更细的样本级产物），
而不是对 3 个汇总量做重采样。

---

## 业务指标组合

### 预警业务

**关注**: POD（不能漏报）

**兼顾**: FAR（避免过多误报）

**推荐组合**: POD + FAR + TS

---

### 定量预报

**关注**: BIAS（频率准确）

**兼顾**: TS（整体技巧）

**推荐组合**: BIAS + TS + 定量误差（MAE/RMSE）

---

### 强降水预警

**关注**: TS@25mm 或 TS@50mm

**兼顾**: POD@25mm（不能漏）

**推荐组合**: TS@25mm + POD@25mm + FAR@25mm
