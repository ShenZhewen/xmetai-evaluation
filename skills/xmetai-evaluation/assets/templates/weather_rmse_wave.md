# 纬向 FFT 与球谐谱补充分析报告骨架

覆盖吃 `weather_rmse_single_<模型>` 产物（`scores.csv` + `manifest.json` +
`diagnostics/`）的那份**补充分析报告**——在单成员报告的口径之上再加
**纬向 FFT 功率谱**与**球谐带功率谱**两套谱检验。
确定性单成员那一份是 [`weather_rmse_single.md`](./weather_rmse_single.md)，集合那一份是
[`weather_rmse_ens.md`](./weather_rmse_ens.md)——三者是同一家族的三个口径：
`_single` / `_ens` 按指标族分，这一份专管**谱**。

**照这个填空就是最终报告。** `{…}` 是占位符，**其余每一个字逐字照抄，不许改**——
包括标点、加粗、表头与分隔行、图注的位置。

## 与另外两份骨架的差别

章节、表头、口径说明全部照原件，只是**原件本身**和 `weather_rmse_single.md` 那份不一样：

- **章节用 `# 1.`…`# 7.` + 附录**，比 `weather_rmse_single.md` 短。这是一份**补充报告**：
  不重复原报告的逐变量 RMSE / ACC 明细，只走「总体结果 → RMSE 分变量 → 功率谱检验 →
  异常与风险 → 验收建议」这条链，末尾用红字声明它不替代原报告；
- **表不编号**，直接跟在章节标题下；**图带 `图 N：` 图注**，编号按出现顺序连续。
  报告里有条件章节（异常检出、缺席模型声明），表一旦参与全局编号，
  条件章节一消失后面全要重排；
- **原件是语雀导出**，带 `<font style="color:#…">` 彩色标签和语雀 CDN 图片链接。
  这里按本地 markdown 规范落地：**彩色标签去掉、只留文字**（「报告性质」「总体判定」
  两句仍然加粗），图片换成 `![名字](名字.png)`——**正文一个字没动**；
- **表格里的 `|pred/obs−1|` 会截断 markdown 表格**，这里写成 `\|pred/obs−1\|`。
  渲染出来还是 `|pred/obs−1|`，只是不再破坏表格结构；
- **中文数字由渲染器给**。原件写的是「三模型」「六个变量」「五个球谐总阶数频带」，
  不是「3 模型」「6 个变量」——`{模型数}`、`{FA变量数}` 这类占位符要填**中文数字**，
  只有 lead、波数、日期数、百分比这些才填阿拉伯数字。

## 编号契约

分三个互不干扰的命名空间——

- 正文用 `图 N：`，编号从 `1` 起、不重号、不跳号到用不到的号；其中 `图 1`–`图 7`
  与 `图 10` 是**必出**（前者每个批次都有对应数据，后者是综合评分的雷达图，只要
  跑得出报告就画得出），`图 8`–`图 9` 按数据可得性出——出不了的那一节**保留节位、
  写明「本批未出」及原因**，不指一张不存在的文件（所以出现「图 8 缺、图 9 在」
  是正常的，缺的是哪一节，那节的标题下面写着）；每张出得来的图必须在正文里出现过；
  `图 10` 排在可选段、`图 8`–`图 9` 之后仍是**必出号**，所以它的缺失不是
  「本批未出」而是渲染器坏了——`图 8`、`图 9` 允许缺席，`图 10` 不允许；
- 分纬度带可选块用 `图 L1：`…`图 L2：`，块内从 1 连续；
- 分季节可选块**预留** `图 S1：`…`图 S2：`；这一块目前本批未出，所以现在不出图、
  号留空（见文末「附 S」）。

**可选块**：两份骨架里都放在报告末尾——`## 附 L 分纬度带结果（可选）` 与
`## 附 S 分季节结果（可选）`，位置在 `# 附录：数据与复算证据` 那张表之后。
整块删掉（连它的表、图注、`图 L*`/`图 S*` 一起删）**不需要重排任何编号**，
这就是给它俩单开命名空间的原因；要用就整块留着，不要只删图不删表。

两块的数据都来自评测产物里**同一张长表**（`region` 列 + 起报时刻），
**不是**另跑一次评测。拿不到数据时**保留节位并标注「本批未出」**，
不静默省略、也不留空表——与下面 §5.1–5.3 球谐带那三节同一套约定。

**§5.5–5.7 是本次补的三节**：原件是语雀导出的旧报告，只有到 1–128 波数为止的谱分析。
补的三节都用**同一批共同日期**的产物数据，作用是把谱上的结论与 RMSE 侧对上——
谱上「小尺度偏低」如果 RMSE 侧没有对应信号，就得在正文里说清楚，不能只报谱。

## 原件没有、这一份补上的东西

原件是**语雀富文本导出**，图是裸 CDN 链接、一张图注都没有。这一份给每张图
**起了文件名、补了 `图 N：{图注}`**——否则"根据评测结果出图"时，
没有任何地方说明这张图该画成什么样。**这是唯一一处对原件的增补**，
不想要就把 `图 N：…` 那几行删掉，其余照旧。

> **本骨架目前没有测试守着**（`tests/` 在这个仓库里是空的，见 `README.md`
> 的「怎么被保证」）。按同一套格式写、能被 `assert_matches_skeleton` 直接认，
> 但**没有**对应的 `test_weather_rmse_wave.py`；将来写渲染器时得自己回来
> 对一遍骨架，别指望 CI 红给你看。
> **占位符不要跨行写**——`{` 和 `}` 两边都算占位符标记。
> **`{报告日期}` 填报告的生成日期**（`YYYYMMDD` 八位，`det_report.report_date()`
> 就是它），**不是数据末日期**——数据覆盖到哪天，正文第 2 节已经写了
> 「覆盖 N 天（起，止）」，抬头这一格只承载「这份报告是什么时候出的」。
> 代价是产物**不再逐位可复现**：同一天跑两次一样，隔天跑就不同。

> **球谐带那三节（5.1–5.3）的数据来自长表里 `spherical_bands` 展开的三行**
> （`spherical_band_power_forecast` / `_observation` / `_ratio`），
> 靠 **`group` 列**区分频带（`1_4` / `5_20` …）。
> **两种情况会让这三节出不来**：配置的 `metrics` 里压根没有 `spherical_bands`；
> 或者算了、但产物**缺 `group` 列**（长表契约 24 列，修复前的产物只有 23 列，
> 5 个频带的行混在一起认不出来）。后者**重跑评测即可**。
> 两种情形渲染器都保留节位并标注「本批未出」，不静默省略、也别留空表。

## 5.7 模型能力雷达图

这一节把 §5.1 那张总表的**综合评分**摆成多边形：每根轴一种能力，每个模型一个
多边形，**越靠外越好**。它不引入任何新算法，只是把总表的数换个读法——看的是
「能力形状」，不是「谁排第一」：两个模型综合分接近时，雷达图能显出差距集中在
哪几项上。谱上的差距会同时反映到两根谱轴上，所以谱明显偏低的模型在这里会凹
进去两块，那**不是两次独立扣分**，是同一件事。

共 5 根轴，方向已在括号里标明（越高越好 / 越低越好）：综合相对RMSE（越低越好）；
ACC (%)（越高越好）；FA偏差 (pp)（越低越好）；谱 logRMS 1–720（越低越好）；
谱 logRMS 1–128（越低越好）。

**读法**：纵轴 0–1 是**批内相对分**，每根轴上 1 = 本批最好、0 = 本批最差
（各轴方向先行统一）。这是{模型数}个模型互比出来的相对位置，**不是绝对能力分**
——全批都差时每根轴照样有人拿 1。某一根轴上所有模型打平时，该轴一律画在满格
1.0（画成 0 会让多边形凭空凹进去），所以**满格不代表领先**，要回正文看绝对数值。
