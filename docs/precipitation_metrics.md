# 降水评测指标说明

## 概述

降水评测采用分类评分方法，将降水量按不同阈值分级，统计预报与观测的命中、漏报、空报情况，计算 TS、POD、FAR、BIAS 等指标。

## 评测流程

### 1. 数据准备

**预报数据**：
- 来源：FuXi 模型输出（NetCDF 格式）
- 变量：累积降水量 (tp)
- 时间步长：6 小时
- 空间分辨率：0.25° 经纬度网格

**观测数据**：
- 来源：Diamond 3 格式逐小时站点降水
- 文件命名：`YYYYMMDDHH.000`
- 时间语义：**文件代表小时结束时刻**（例如 `2025010208.000` = 北京时 2025-01-02 08:00 结束的 1 小时累积降水）

### 2. 时空对齐

**时间窗口累积**：
- 24 小时窗口 = 闭区间 `[V-23h, V]`（V 为验证时刻，北京时）
- 预报：对 6 小时步长的预报场求和（例如 lead=24h 时，累加 index 0-3 的 4 个时次）
- 观测：累加验证时刻前 24 个小时文件的降水量

**空间插值**：
- 方法：双线性插值（bilinear）
- 将格点预报插值到站点位置
- 保留站点经纬度和海拔高度信息

**站点完整性检查**：
- 窗口内任一小时缺测 → 该站点剔除
- 0 降水是有效记录（不视为缺测）
- 只评估完整站点（valid_mask）

### 3. 时效选择

**完整窗口边界**：
- 24h 窗口只评估 24h、48h、72h、96h、120h... 等完整窗口边界时效
- 不评估 30h、42h 等非边界时效
- 原因：避免窗口重叠导致的样本相关性

## 分类评分指标

### 阈值定义

降水量按以下阈值分为 6 个等级：

| 等级 | 阈值 (mm) | 含义 |
|------|-----------|------|
| ≥0.1 | 0.1 | 微量降水（有/无降水分界） |
| ≥10  | 10.0 | 小到中雨 |
| ≥25  | 25.0 | 中到大雨 |
| ≥50  | 50.0 | 大到暴雨 |
| ≥100 | 100.0 | 暴雨到大暴雨 |
| ≥250 | 250.0 | 特大暴雨 |

**超越式阈值**：`降水量 ≥ 阈值` 判定为"发生"，`< 阈值` 判定为"未发生"。

### 列联表

对每个阈值，统计预报与观测的四种情况：

|              | 观测：发生 | 观测：未发生 |
|--------------|-----------|-------------|
| **预报：发生**   | 命中 (hits) | 空报 (false_alarms) |
| **预报：未发生** | 漏报 (misses) | 正确否定 (correct_negatives) |

**样本对数** (n_pairs)：有效站点数 × 起报次数

### 核心指标

#### 1. TS (Threat Score / CSI - Critical Success Index)

$$
TS = \frac{hits}{hits + misses + false\_alarms}
$$

**含义**：
- 衡量预报的**整体准确性**
- 考虑了命中、漏报和空报三种情况
- 取值范围：[0, 1]，1 表示完美预报

**特点**：
- 对小样本敏感（罕见事件 TS 偏低）
- 不受"正确否定"影响（适合评估降水等稀疏事件）
- **越高越好**

**典型值**：
- ≥0.1mm：TS > 0.5 为良好
- ≥25mm：TS > 0.3 为良好
- ≥100mm：TS > 0.1 为良好（暴雨预报难度大）

#### 2. POD (Probability of Detection / 命中率)

$$
POD = \frac{hits}{hits + misses}
$$

**含义**：
- **观测到的事件中，预报命中的比例**
- 回答"实际下雨时，预报对了几次？"
- 取值范围：[0, 1]，1 表示无漏报

**特点**：
- 只关注漏报，不关注空报
- 预报保守（阈值低）→ POD 高、FAR 高
- **越高越好**

**典型值**：
- ≥0.1mm：POD > 0.7
- ≥25mm：POD > 0.5
- ≥100mm：POD > 0.3

#### 3. FAR (False Alarm Ratio / 空报率)

$$
FAR = \frac{false\_alarms}{hits + false\_alarms}
$$

**含义**：
- **预报发生的事件中，实际未发生的比例**
- 回答"预报下雨时，报错了几次？"
- 取值范围：[0, 1]，0 表示无空报

**特点**：
- 只关注空报，不关注漏报
- 预报激进（阈值高）→ POD 低、FAR 低
- **越低越好**

**典型值**：
- ≥0.1mm：FAR < 0.3
- ≥25mm：FAR < 0.5
- ≥100mm：FAR < 0.7（暴雨预报允许更高空报率）

#### 4. 漏报率 (Miss Rate)

$$
漏报率 = \frac{misses}{hits + misses} = 1 - POD
$$

**含义**：
- **观测到的事件中，预报漏掉的比例**
- 与 POD 互补（POD + 漏报率 = 1）
- 取值范围：[0, 1]，0 表示无漏报

**特点**：
- 与 POD 提供相同信息，但表达方式不同
- 某些业务习惯用漏报率而非 POD
- **越低越好**

#### 5. BIAS (频率偏差)

$$
BIAS = \frac{hits + false\_alarms}{hits + misses}
$$

**含义**：
- **预报发生次数与观测发生次数的比值**
- 衡量预报的**系统性偏差**
- 取值范围：[0, +∞]

**判读**：
- BIAS = 1：预报频率与观测一致（**最优**）
- BIAS > 1：预报偏多（过度预报，倾向于"宁可错报不可漏报"）
- BIAS < 1：预报偏少（预报保守，倾向于"宁可漏报不可错报"）

**特点**：
- **不反映预报准确性**，只反映频率偏差
- 可以 BIAS = 1 但 TS 很低（预报次数对了，但时空位置全错）
- 与 TS/POD/FAR 配合使用才有意义

**典型值**：
- 0.8 ~ 1.2 为合理范围
- > 1.5 说明预报过于激进
- < 0.5 说明预报过于保守

### 指标关系

**POD、FAR、BIAS 的平衡**：
- 高 POD + 高 FAR = 预报激进（报多了）
- 低 POD + 低 FAR = 预报保守（报少了）
- 高 POD + 低 FAR = 理想状态（TS 高）

**TS 的综合性**：
- TS 同时惩罚漏报和空报
- 当 POD 和 FAR 平衡时，TS 最大化
- TS 无法区分系统性偏差方向（需要结合 BIAS）

## 输出格式

### CSV 文件结构

```csv
window_h,lead_h,grade,threshold_mm,hits,misses,false_alarms,n_pairs,TS,POD,FAR,漏报率,BIAS
24,24,≥0.1,0.1,12345,678,890,50000,0.8523,0.9478,0.0673,0.0522,1.0162
24,24,≥10,10.0,3456,234,456,50000,0.7234,0.9367,0.1167,0.0633,1.0631
...
```

**字段说明**：
- `window_h`：累积窗口小时数（24 = 24 小时累积降水）
- `lead_h`：预报时效（小时）
- `grade`：降水等级标签
- `threshold_mm`：阈值（毫米）
- `hits`：命中次数
- `misses`：漏报次数
- `false_alarms`：空报次数
- `n_pairs`：样本对数（站点数 × 起报次数）
- `TS`：威胁评分
- `POD`：命中率
- `FAR`：空报率
- `漏报率`：1 - POD
- `BIAS`：频率偏差

### 典型结果示例

**微量降水（≥0.1mm）**：
- TS = 0.85（准确性高）
- POD = 0.95（命中率高）
- FAR = 0.07（空报率低）
- BIAS = 1.02（频率接近观测）

**大雨（≥25mm）**：
- TS = 0.45（准确性中等）
- POD = 0.60（漏报 40%）
- FAR = 0.30（空报 30%）
- BIAS = 0.86（预报偏保守）

**暴雨（≥100mm）**：
- TS = 0.12（准确性低，罕见事件难预报）
- POD = 0.25（漏报 75%）
- FAR = 0.60（空报 60%）
- BIAS = 0.63（预报明显偏少）

## 注意事项

### 1. 站点完整性

**严格要求**：窗口内任一小时缺测 → 剔除该站点
- 保证窗口累积的一致性
- 避免部分累积带来的系统性误差
- 代价：样本量减少（n_excluded 列）

**影响**：
- 通信故障多的地区样本量少
- 边界站点可能被大量剔除
- 需要关注 `n_pairs` 是否足够

### 2. 时间语义

**北京时对齐**：
- 预报：UTC 起报 + 8 小时时区转换
- 观测：文件名直接表示北京时
- 验证时刻：`init_time + lead_hours + 8`

**窗口定义**：
- 24h 窗口 = `[V-23h, V]`（闭区间）
- 观测文件代表小时**结束**时刻
- 例如：V = 2025-01-03 08:00，窗口 = 01-02 09:00 ~ 01-03 08:00

### 3. 罕见事件评分

**小样本问题**：
- 暴雨事件少 → TS 低、指标波动大
- 需要更长评测周期（全年或多年）
- 单次起报可能无暴雨样本（n_pairs > 0 但 hits + misses = 0）

**建议**：
- ≥100mm：至少评测 3 个月
- ≥250mm：建议评测全年或多年
- 关注 `n_pairs` 和事件发生率（hits + misses）

### 4. 插值误差

**空间分辨率差异**：
- 预报：0.25° 网格（~25km）
- 观测：点观测（站点）
- 插值引入平滑误差（尤其是对流性降水）

**影响**：
- 小尺度强降水中心可能被削弱
- 边界站点插值误差大
- 山区站点海拔差异影响大

## 常见问题

### Q1：为什么暴雨的 TS 这么低？

A：这是正常现象。暴雨事件罕见（样本少），且难以预报（时空精度要求高）。国际上暴雨 TS > 0.1 已经算不错的表现。

### Q2：BIAS = 1 但 TS 很低，是什么问题？

A：预报频率对了，但时空位置错了。典型情况：
- 该下雨的地方没报，不该下雨的地方报了
- 时间对了，位置错了（或反之）
- 需要检查预报的时空分布是否合理

### Q3：如何判断预报是否有业务价值？

A：综合考虑：
- **TS**：整体准确性（主要指标）
- **POD**：不能太低（避免漏报太多）
- **FAR**：不能太高（避免虚警太多）
- **BIAS**：接近 1（系统性偏差小）
- **业务需求**：防汛偏好高 POD（宁可错报），交通偏好低 FAR（减少虚警）

### Q4：为什么只评估完整窗口边界时效？

A：避免样本相关性。如果评估 24h、30h、36h...，则：
- 30h 窗口与 24h 窗口有 18 小时重叠
- 样本不独立 → 统计检验失效
- 完整边界（24h、48h、72h）无重叠 → 样本独立

### Q5：n_excluded 很大，会影响结果吗？

A：取决于剔除原因：
- 均匀剔除（通信故障）→ 影响小
- 系统性剔除（某些地区或时段）→ 可能引入偏差
- 建议检查剔除站点的空间分布和时间分布
