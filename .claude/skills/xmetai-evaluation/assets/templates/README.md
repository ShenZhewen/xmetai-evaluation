# 报告模板

一个评测能力对应一份报告骨架。

## 骨架是什么

**一份完整的报告，只是数值位置空着。**

打开 `ts.md` 看到的，就是最终 `REPORT.md` 的样子——章节、导语、表头、分隔行、加粗、
标点、口径说明的每一句话，全都是真的；只有具体数字和逐条结论用 `{…}` 占住了。

**生成报告 = 把 `{…}` 换成算出来的值，其余一个字都不动。**

**图注、表题、每节的 `**小结**` 也是骨架的一部分**，不是渲染器的自由发挥：
骨架规定了它们**出现在哪里、以什么形式出现**（图注在图下方、表题在表上方，
写成 `图 N：…` / `表 N：…`，编号按出现顺序连续），渲染器负责填里面的文字。

所以同一能力不同批次出来的报告，格式必然一样、只有内容不同，
两批结果能并排看、能逐节对比。

## 占位符约定

| 写法 | 含义 |
|---|---|
| 行内 `{…}` | 这一行里的一小段值（模型名、时效、路径…） |
| 整行就是一个 `{…}` | 这里展开成**若干行**（逐条结论、表体行、图列表） |
| `{本次改动说明}` | **可选**：只有调用方给了 `--change` 时这一行才出现 |

## 骨架不是什么

- **不是模板引擎**。没有程序去读它做字符串替换，它不参与渲染。
  报告是 `ts_report.py` 的 `build_ts_report()` 逐行拼出来的——
  真搞一套占位符替换，等于在 Python 之外再养一份渲染逻辑，两边迟早不一致。
- **不是判读文档**。数字怎么解读看 `references/*.md`；骨架只管**长什么样**。

## 怎么被保证

`tests/unit/visualization/test_ts_report.py` 里有两组用例：

1. **章节序列**——把骨架里的 `##` 标题序列和真报告逐项比对（`{…}` 当通配符）；
2. **逐字行**——骨架里**所有不含占位符的行**，必须在真报告里逐字出现、且顺序一致。

这两组有个共同的盲区：**含 `{…}` 的行它们一句话都钉不住**——而图注、表题、小结
恰好全在这种行里。所以另有一组**编号与排版契约**用例补上：

- `图 N：` / `表 N：` 必须各自是 `1..N` 连续，不跳号、不重号（`_captions` + `_assert_sequential`）；
- 每个分析节末尾都要有一行 `**小结**：`，且**里面得有数字**——防止退化成"模型表现良好"这种空话；
- `create_report` 出的每一张图都得在报告里被安排过位置（`test_every_artifact_is_placed_in_the_report`），
  以后加了新图却忘了写进报告，这条会红；
- 产物里缺图时**连图注一起不出现**、后面的编号也不留空档。

代码漂了、或者骨架忘了同步，这几组都会红。
这也是"格式一样"不靠自觉、而是被机器守着的原因。

三个分支（A 单模型 / B 单基准 / C 多模型）各有对应的端到端用例，
分别断言真报告能对上哪一份骨架——章节序列与逐字行都不许漂。

## 加一份新骨架

1. 在本目录加 `<家族名>.md`，照 `ts.md` 的写法放 `<!-- skeleton: <分支名> -->` + ```` ````markdown ```` 块，
   一个分支一块；
2. 在 `tests/unit/visualization/` 加对应的比对用例；
3. 回来更新本文件的索引表。
